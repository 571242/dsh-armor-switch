# 第一批维护修改

本批只实现插件详情页的只读诊断与现有改动恢复，不实现新的清洗开启、权限提升或指令改写。

## 原文保留

CONTRACT_TEXT、AUTHORITY_TEXT、MECHANISM_TEXT、BLOCK_BODY 和 TARGETS 的原始源码片段已记录 SHA-256，并加入回归断言。[哈希基线](<../tests/instruction-hashes.json>)。两个旧清洗模块的内容没有修改。

## 入口

客户端不再注册聊天输入框的 composer dock。维护面板只注册到 plugins.bundle.config，key 为 dsh-armor-switch，出现在本插件详情页。

可重新检查、恢复宿主、恢复当前 profile，或恢复两项。恢复要求在页面再次确认。面板显示磁盘状态、恢复凭据异常与待重启提示；它不宣称能验证本进程已经重新加载磁盘内容。

## 恢复语义

- 宿主：验证 manifest 对应同一归档、大小相同、目标合法、原始/改写备份校验正确；全部跨度预检通过后才写回原始字节。缺备份、记录不完整或跨度漂移时不盲写。不覆盖或删除 manifest。
- profile：以当前运行环境的 DSH_PROFILE_DIR / DSH_PROFILE 为优先依据；歧义时不猜 desktop。只删除完整且未经编辑的生成块，缺标记、重复标记或内容被改过时拒绝自动删除。块外字节完整保留，先备份再写回。
- RPC：恢复失败返回 ok:false，value.operation.outcomes 保留每项结果；一次恢复中另一项成功不会被隐瞒，也不把失败项说成成功。
- 启动：维护版仅作只读检查，不再自动施加磁盘改写，因此恢复后下一次启动不会重新清洗。
- 当前会话：恢复磁盘不主动更改任何运行会话的权限。加载态需重启后验证；本批没有自动重启。

## 测试

在项目根目录运行 `node tests/maintenance.mjs`。夹具仅写入新建的系统临时目录，不调用真实清洗，运行后会打印夹具路径供排查。原自检的 apply 调用也已限定为临时目录中的明确路径。

本批已验证不完整标记不误删、配置块外字节保留、归档漂移拒写、备份校验、归档身份匹配、逐项失败反馈、状态重新读取、插件页槽位和网络失败保留确认态。

## 普通偏好编辑器（1.1.0）

插件页“破甲”标题后有 ✎ 按钮，打开普通角色与交付偏好编辑框。它不读取或替换内置指令、破甲覆盖文本和权限规则。支持查看、手动修改、保存与留空恢复默认。

偏好单独保存为当前 profile 中的 `armor-switch.preferences.json`，保存使用版本校验和原子替换。原文保留在独立区段，关闭变量插值；固定来源说明明确这些内容不能改变指令优先级、安全要求或工具权限。

新增测试入口 `node tests/preferences.mjs`，覆盖保存、重读、冲突拒绝、格式错误保留、编辑框打开、草稿与确认值区分、网络失败处理，以及独立区段与原有指令隔离。

## 部署与后续范围

本机安装采用先备份、后同步插件文件的方式；状态以本轮部署回执为准。安装不修改真实宿主归档、profile 配置、依赖登记或清洗 manifest。插件宿主代码及客户端清单更新后，需要重启 DSH 才能确认运行态已加载新版本。

浏览器工具目前缺少 bsk，页面点击与实际重启验证尚未完成。卸载前恢复确认以及历史文档/旧 RPC 的进一步清理，留到后续单独调整。原始指令文本继续受哈希回归保护。
